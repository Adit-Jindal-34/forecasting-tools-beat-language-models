# Forecasting tools beat language models on time-series questions

Code and results for a benchmark that puts the same time-series question to two
designs and scores them identically: one writes the numbers into the prompt and
lets the language model answer, the other gives the model a menu of tools and
lets it choose.

**Blog post:** _[add the Substack link here once the post is published]_

Routing to a small forecasting tool beat the model alone in all fourteen
configurations tested. On 300 real series the tool scored 0.639 against 0.456
for the model alone, with a naive baseline that copies the previous cycle at
0.569.

## Layout

| path | what it is |
|---|---|
| `ts-arch-bench/` | cycle 2: the fourteen configurations on generated series |
| `ts-arch-bench-c3/` | cycle 3: the real-data runs on 300 Monash series |
| `blog/` | the figures, and the scripts that build them |

The two trees are deliberately separate. Cycle 3 was written in its own folder so
the cycle-2 code, including the gpt-oss runs, stays exactly as it was when those
results were produced.

## Reproducing the figures

The analysis files each figure reads are committed, so the figures rebuild
without a GPU:

```bash
python blog/make_figures.py
python blog/make_animation.py
```

## What is not in this repository

**Cached per-item results.** `raw_results.csv` and the `shards/` directories hold
one row per model answer and come to about 150 MB. They are regenerated by
rerunning the pipeline, and the analysis files committed here already contain
every number the blog post reports.

**Superseded runs.** Four result directories from earlier runs, made with earlier
code, are left out on purpose. Only the runs from 13 to 15 November 2026 are used.

**`env.sh`.** It holds local paths and would hold any provider key. Copy
`.env.example` and fill it in.

**Cluster logs.** Slurm output and vLLM server logs are not published.

## Scoring

Forecasts are scored as

```
score = 1 / (1 + MASE)
```

MASE is the average error of the forecast divided by the average error of a naive
forecast on the same series, using a denominator fixed per item so that scores at
different history lengths stay comparable. A score of 0.5 means the forecast and
the naive forecast made the same average error.

## Pre-registration

`PREREGISTRATION.md` and `PREREGISTRATION_C2.md` in `ts-arch-bench-c3/` record the
comparisons, the decision rules and the effect-size thresholds, all fixed before
any model was run. One pre-registered prediction failed and is reported as a
failure: more history did not widen the gap between the two designs.
